# 0.1.3 lifecycle repair

Reference: local codex-acp `CodexAcpServer.ts`: `loadSession` awaits
`streamThreadHistory`; `beginSessionOpen` / `sessionOpenCanInstall` guard stale
opens; turn completion follows the runtime's authoritative completion event.
ACP references: https://agentclientprotocol.com/protocol/v1/session-setup and
https://agentclientprotocol.com/protocol/v1/prompt-turn.

Pi-specific implementation:

- History replay queues Pi-projected updates, then explicitly drains them before
  acknowledging `session/load`. A 12-turn regression previously received only
  one of 24 history messages at acknowledgement.
- Every session open owns a generation. Superseded or closed opens dispose their
  runtime instead of installing it. Disposal also waits for in-progress opens.
  Concurrent resume previously left one of two runtimes unclosed.
- Notification delivery errors are sticky and propagate through `flush` and
  prompt completion. Teardown still disposes resources after a delivery error.
- Pi's `agent_settled` begins completion, but the turn remains active until its
  final updates drain. Completion snapshots its stop reason and cancellation
  state before waiting. New prompts wait for a draining turn rather than
  mutating its projection.
- Failed model-runtime initialization is not permanently cached.
- Session close is idempotent. Stdout transport captures its writer before
  runtime extensions can redirect the global writer.

Backchat companion change (not part of this npm package): setup probes validate
UTF-8 / JSON frames before passing them to the ACP SDK. Invalid frames terminate
the disposable connection and release its process instead of waiting for the
90-second request deadline. A malformed-response regression failed with the old
implementation and succeeds with the guard. This does not bypass startup with
an arbitrary UI timeout.

Known investigation limit: the original captured response lost its ending before
a `session/update` notification. Ten independent installed-adapter probes across
Node and Electron did not reproduce it. The original source of byte loss is not
proven. The stdout ownership defect is independently reproduced; it must not be
presented as proof of the original truncation's root cause.

Validation: real Pi runtime with the faux provider (no model network calls),
history delivery ordering, concurrent resume cleanup, close during resume,
notification failure, draining turn state, initialization retry, cleanup after
transport failure, and real subprocess stdio framing with large UTF-8 messages.

Release correction: 0.1.2 (9cca36c) was accepted by npm before the workflow cancellation completed and became visible after registry processing. It contains only the stdout ownership fix. 0.1.3 contains the lifecycle repairs above; the published 0.1.2 tag is preserved.
